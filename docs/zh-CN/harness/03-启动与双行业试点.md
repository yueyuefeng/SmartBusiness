# 03 启动与双行业试点

除明确写明切换目录外，以下命令均在 SmartBusiness 仓库根目录执行。业务工作台不需要模型 API 密钥；Harness 会话调用模型需要用户自己的有效凭据。

本轮固定 `@deepseek-ai/dsh@0.1.6-alpha.2`，插件锁定 `@deepseek-ai/cordis@4.0.2` 与同版本 dsh-tools/dsh-system-prompt。源码核对提交为 `ddefc45fbc7f8e46dd73185e68295696d1297887`。插件声明 Node.js `^22.19.0 || >=24.0.0`，本轮本机实测 Node 24.21.0、Python 3.14；没有据此声明其他操作系统已完成实机验证。

## 1. 启动工作台

先确认 Python 可运行，再执行：

```text
python --version
python -X utf8 -m smartbusiness serve --port 8787
```

浏览器打开 `http://127.0.0.1:8787`。服务启动后保持终端运行，停止时在该终端按 Ctrl+C。本地数据与凭据保存在 `.smartbusiness/`，该目录被 Git 忽略；保留目录即可在下次启动继续使用记录。备份业务数据前停止服务并复制整个数据目录，令牌备份须与普通报告分开保管。当前没有在线备份、加密备份或自动恢复演练功能。

原生响应式 Web 可随窗口宽度适配布局。本轮绑定本机回环地址，手机不能直接访问另一台电脑的 `127.0.0.1`；没有把手机远程访问、商店安装包或局域网部署算作已完成。

## 2. 启动 Harness

安装 Node.js 后，首次进入插件目录安装锁定依赖：

```text
cd integrations/deepseek-harness
npm ci
npm test
cd ../..
```

保持业务服务终端运行，另一个终端在仓库根目录执行：

```text
python -X utf8 -m smartbusiness harness
```

启动器负责把业务 API 地址、Agent 令牌和本地插件路径接入 Harness，并把 `DSH_HOME` 指向 `.smartbusiness/harness-home`，设置 `DSH_TOOLS_MODE=native`。使用仓库固定的运行版本，不自行改成浮动 `latest` 后仍宣称兼容。首次依赖下载需要网络。

可用 `serve --data-dir <目录> --port 8787` 自定义本地数据位置；对应的 `harness --data-dir <同一目录> --api-port 8787 --port 3080` 必须连接到同一个业务服务。不要把端口改动只应用在其中一个进程。

首次打开终端打印的 Harness 地址（带 `?token=...` 的本地登录令牌），在初始引导或 Settings → Models 中填写模型凭据；也可选“稍后配置”先查看界面。登录后可通过工作台的默认 3080 端口链接再次进入。不要把登录令牌提交到仓库或复制到公开报告。选择一个专用试点工作目录后开始会话。官方文档说明，新建 Web 会话需要先选中工作目录，模型设置可以在界面完成。[官方 Web 使用说明](https://deepseek-harness.github.io/deepseek-harness/en/guide/quickstart)

建议试点使用无敏感文件的专用目录。当前插件的精确工具白名单会拒绝工具管线中未列明的工具，但不是同进程插件或操作系统沙箱；正式项目资料应等到运行时隔离完成再导入。

没有凭据时可先完成全部离线试点。离线工具测试和插件加载验证不等于真实模型调用成功，模型对工具的选择、费用和回答质量要在配置后另外验收。

## 3. 一个真实记录试点

使用操作者实际取得且有权使用的资料，按下面流程保存记录。没有真实材料时可以填明确标注的演练内容，不把演练内容作为商业证据。

本轮以六个案例 ID 作为行业试点归类入口。新记录可以来自实际访谈，但不能因此采用该合成案例的虚构报价、供应商和利润作为实际事实。

1. 在情报中记录一个客户问题，并填写信息来源与时间。
2. 建立一个商机提案，写清目标客户、地区、问题、价值假设和下一项验证。
3. 登记一个供应资源，状态保持待核验；创建核验任务，要求提供主体、能力和有效报价。
4. 登记联系人并保存本地沟通笔记，明确这不是社交平台原始收发记录。
5. 创建营销草稿，凡是性能、价格、节省、续航和减排表述都说明证据或假设。
6. 由操作者进行内部内容审核；审核完成后内容仍不会发布到任何外部平台。
7. 为合同、软件、硬件或 ESG 建立工作项，写清验收条件，记录执行结果和资料位置。贸易订单和履约模块待后续开发。

这一流程产出可追踪的业务准备记录，尚不构成签约、交付、利润实现或法定披露。

## 4. 能源行业试点

工作台运行 EN-H01、EN-H02 和 EN-C01，分别代表家庭光储备电、家庭电热协同、商业储能。也可使用命令运行全部行业案例：

```text
python -X utf8 -m industry_pilots.runner --output examples/results/industry-report.json
```

第一轮关注这些问题：

- EN-H01：备电峰值功率和可用电量是否分别满足？安装、质保成本是否进入贡献利润？
- EN-H02：光伏、电池、热泵、储热是否按电/热侧分开？计算期末存量是否可比？
- EN-C01：计算窗口能否支持电费判断？不完整计费期不得声称完整需量收益或年化回报。

默认市场尚未确认，样例中的资源、价格、负荷与证据均为合成数据。把运行产生的缺口转换为实际任务，例如“确定首个国家/城市”“取得真实场址电价”“复核安装与消防路线”，由责任人获得材料后再建立真实项目。不能通过修改 synthetic 标志把样例升级为实际工程。

可在 Harness 中使用下面的任务描述：

```text
读取 EN-H02 合成案例并调用 SmartBusiness 行业评估工具。
先解释电热分账和当前缺口，逐项引用工具结果。
把需要补充的客户/场址/市场材料整理成工作项草案。
所有案例金额标为估算，不声明可安装、并网或已实现收益。
```

## 5. 出行行业试点

运行 MO-E01、MO-M01 和 MO-K01，分别代表电动自行车、电动摩托和自行车电助力改装。

- MO-E01：使用工况续航区间，明确适用条件；国内一二线城市也必须进一步细分市场资料。
- MO-M01：沿独立摩托路线检查资料，不能把它重命名成自行车以绕过分类问题。
- MO-K01：默认缺少车架评估，保持阻断；套件资料不能替代原车、结构、制动和安装核验。

可以要求 Harness 分析 MO-K01 缺少哪些资料、登记候选安装资源并创建核验工作项。它可以帮助收集和整理，不能在当前系统内授予道路合法性或完成车辆认证。

## 6. 验证与故障定位

```text
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/check_harness_integration.py
python -X utf8 scripts/check_design_docs.py
```

Harness 插件测试在插件目录执行 `npm test`，实际运行时验证按该目录的说明执行。业务测试失败时先修复业务规则或接口，不用调整提示词隐藏失败。插件加载失败时核对固定版本、绝对路径与工具服务注入；API 鉴权失败时确认服务与启动器使用同一个本地数据目录，勿把令牌粘贴进对话求诊断。工作台的 `model_connected=false` 表示业务服务没有探测模型会话连接，不是对另一端官方 Harness 模型设置的在线诊断。

若端口占用，先确认现有进程用途，使用应用支持的端口选项协调业务服务与启动器，不直接结束未知进程。数据库打不开时先确认路径权限和备份，勿删除现有数据目录作为通用修复方法。
