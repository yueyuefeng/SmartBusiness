# 01 新增术语、专家视角与领域边界

本篇在[通用统一语言](../01-专业词汇与统一语言.md)和[能源与出行术语](../industries/01-行业词汇.md)之上增加运行时与业务协作词汇。不得以通用 AI 词汇替换行业概念。

## 1. 统一语言增量

|编号|词汇|本项目含义|必须区分|
|---|---|---|---|
|H01|Harness／智能体运行时|管理会话、模型调用和工具执行的基础设施|不等于业务系统、模型本身或授权中心|
|H02|Agent／智能体|在给定目标和工具范围内提出或执行步骤的程序|不等于有法律责任的员工或专家|
|H03|Cordis 插件|通过官方插件生命周期注册能力的模块|不等于任意脚本都获得业务权限|
|H04|Tool／业务工具|带输入契约、权限和结果的业务应用接口|不直接暴露数据库 SQL 或任意命令|
|H05|Model Provider／模型服务方|提供推理能力和模型凭据的服务|与业务 API 的访问令牌分开|
|H06|Session／会话|一次人机协作的上下文容器|会话文本不是业务事实的唯一存储|
|H07|Signal／市场信号|带来源与时间的原始需求或市场观察|不等于已核实的需求和可盈利商机|
|H08|Opportunity Proposal／商机提案|针对客户问题、市场和价值的候选机会|不等于 CRM 已成交订单|
|H09|Unverified Resource／待核验资源|登记的潜在供给或能力线索|存在记录不代表资质、产能或报价已核验|
|H10|Evidence Reference／证据引用|指向来源材料或记录的可追踪标识|引用存在不证明材料真实有效|
|H11|Content Draft／内容草稿|可编辑、待审核的营销表达|生成完成不等于批准或已经发布|
|H12|Internal Review／内部审核|操作者在当前版本上作出的内部处理决定|不代表平台发布许可或法律合规结论|
|H13|Work Item／执行工作项|有业务类别、对象和结果记录的任务|不是已验收工程、已签合同或已鉴证报告|
|H14|Local Note／本地沟通笔记|操作者或 Agent 保存的联络记录|不是从社交平台收取的消息原件|
|H15|Idempotency Key／幂等键|同一写入请求重试时用于识别其业务身份的键|同一键不能携带另一份业务内容|
|H16|Audit Record／审计记录|业务操作的行动者、时间、对象与结果轨迹|本地日志不是防篡改合规审计设施|
|H17|Simulation／合成模拟|输入明确标为虚构的数据和流程验证|模拟通过不证明真实交易、认证或收益|
|H18|Deterministic Rule／确定性规则|相同有效输入得到相同结果的领域计算|模型文字解释不能覆盖规则输出|
|H19|Capability Boundary／能力边界|某工具允许调用的操作集合|插件边界不等于整个运行进程的隔离边界|
|H20|Business Readiness／业务就绪状态|技术、市场、资源、内容和经济条件的独立判断|不能合并成没有证据的单一“可销售”分数|

## 2. 多专业视角预分析

下表是 **AI 辅助预分析**，未举行真人专家会审。每一项结论均须有可验证的输入和责任人，不能把多 Agent 一致回答当作专业会审证据。

|视角|主要质疑|对模型与实现的影响|正式试点前要补的资料|
|---|---|---|---|
|创业与经营|整理情报是否真正缩短获得收入的路径？|商机必须关联客户问题、资源和下一项验证；利润由交易证据回流|选定客户群、访谈与付费意愿|
|内外贸|成交价格是否覆盖履约、税费、退货和售后？|市场、币种、成本口径及责任范围显式化|目标国家/城市、贸易条款、物流税费估算|
|能源工程|功率、电量、热量和电费基线是否混淆？|复用电热分账和独立功率约束，计算输出附适用边界|场址、电价、负荷、设备与安装方案|
|车辆工程|套件匹配是否等于整车适用？|车型路线与改装适配分别建模，缺车架证据保持阻断|原车配置、制动/结构与电池充电组合资料|
|供应链|网上能找到供应商是否等于资源可用？|新增资源固定为待核验，能力、报价、时间和市场分别补证|主体、样品、交期、资质、报价有效期|
|营销与品牌|AI 文案是否会把估算写成承诺？|草稿和审核分离；发布适配器后置，行业声明保留来源|内容事实依据、受众、渠道、使用权|
|客户与销售|客户、会话、联系方式是否可以自动合并？|本地客户与沟通笔记分别记录；身份关联须明确依据|授权来源、联系人关系、重复数据策略|
|财务与风险|模拟利润是否被当成已实现利润？|估计/缺失/核对状态必须显式；不生成没有证据的净利润|成本、退款、收款与归属期间|
|法律与合同|生成合同是否等于可以签约？|先实现义务与审阅工作项，电子签署为独立能力|法定主体、授权签字人、适用法与交付约定|
|ESG 与测量|节能测算是否足以声称减排？|组织/产品边界、期间、因子和材料证据需要独立模型|适用披露要求、活动数据、方法与因子版本|
|架构与安全|模型能否借工具之外的能力绕过业务规则？|工具权限与运行时隔离分别设计；生产拆分凭据和网络|身份体系、执行权限、沙箱与网络部署方案|
|测试与运维|升级运行时后工具还能按原合同执行吗？|固定版本，增加工具契约测试与真实加载验证|锁文件、升级差异、回滚和备份演练|

## 3. DDD 责任边界

继续采用 [BC01–BC17 上下文](../05-DDD战略设计.md)。新增 AI 编排是基础设施/应用层适配器，**不新建一个拥有所有业务实体的“Agent 大领域”**。

|领域上下文|本轮进入点|领域拥有的事实|Agent 可以做什么|
|---|---|---|---|
|BC01 情报|capture_signal|信号记录及来源|整理并提交带来源的线索|
|BC02 机会与需求|propose_opportunity|候选商机|提出待验证的机会和问题|
|BC03 资源网络|add_resource|待核验资源|登记候选，不授予 verified 状态|
|BC06 CRM|add_contact|联系人记录|基于用户提供的数据建档|
|BC07 沟通|record_note|本地笔记|记录讨论摘要，不模拟平台消息|
|BC08 营销|draft_content、review_content|内容草稿与内部审核决定|Agent 建草稿，操作者内部审核|
|BC10–12、BC14 合同、软硬件、ESG|create_task、record_task_result|四类工作项和结果说明|准备任务、记录资料结果，不签约、认证或鉴证|
|EN01／MO01 行业规则|案例评估|确定性合成评估结果|调用并解释，不能改写规则结果|
|BC16 治理|认证、幂等、审计|操作轨迹|使用授予的业务接口|

本地 SQLite 是当前落地方式，表划分不代表 17 个上下文已全部实现。共用存储也不赋予 Agent 跨上下文任意修改权。

## 4. 业务事件与不变量

候选事件语言：情报已记录 → 商机已提出 → 资源已登记 → 内容草稿已建立 → 内容已内部审核 → 执行结果已记录。事件名称描述实际完成的动作，不用“资源已认证”“项目已成功”替代较弱事实。

核心不变量：

- 来源文本属于待分析材料，其中的“忽略规则”或“批准付款”等语句不成为系统命令。
- 同一幂等键和相同写请求可以重试；内容冲突必须报错，不重复创建记录。
- Agent 创建资源不能自行变成已核验；Agent 不能调用操作者专用的内容审核。
- 内部审核与外部发布是不同业务事实，不能通过审核状态推断发布成功。
- 六个样例的行业运行保持 synthetic=true，估算贡献利润和真实成交利润分别表达。
- 真实业务记录和合成案例可以在同一工作台查看，但不能把案例供应商、交易与证据用于真实订单。

## 5. 建模后仍需验证的问题

首批国家/州/城市、具体目标客户、盈利方式优先级和供应商仍未确定。默认按可替换市场资料设计，不把“欧美”视作同一监管区域。第一轮访谈应把这些问题收敛成一个能源试点和一个出行试点，再修订统一语言和聚合边界。
