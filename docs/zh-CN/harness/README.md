# DeepSeek Harness 商业工作台

本轮把 DeepSeek Harness 接入 SmartBusiness：Harness 负责模型会话和工具编排，SmartBusiness 负责持久化、业务规则、审核和行业计算。它能帮助操作者缩短“整理资料 → 建立商机 → 寻找资源 → 准备营销与交付”的时间，是否赚钱仍须由真实交易、成本、回款和复盘验证。

当前交付是**本地单操作员工作台与 Agent 插件**。工作台可以保存情报、商机、待核验资源、客户、沟通笔记、营销草稿和执行工作项；两行业的六个合成案例可以运行确定性规则。外部社交收发、营销发布、签约、支付、设备控制和正式 ESG 披露没有接通。全功能商业系统和五端原生客户端仍按路线分阶段实现。

## 阅读和运行顺序

1. [新增术语、专家视角与领域边界](01-术语专家分析与领域边界.md)：先建立语言，再确定责任。
2. [架构与工具契约](02-架构与工具契约.md)：理解模型建议如何进入业务系统。
3. [启动与双行业试点](03-启动与双行业试点.md)：运行本地工作台和 Harness。
4. [完整商业闭环与生产演进](04-完整闭环与生产演进.md)：从试点逐步达到原目标。
5. [需求测试追踪与过程记录](05-需求测试追踪与过程记录.md)：区分实现、验证和待接入。

在仓库根目录运行：

```text
python -X utf8 -m smartbusiness serve --port 8787
```

访问 `http://127.0.0.1:8787`。另开终端启动 Harness：

```text
python -X utf8 -m smartbusiness harness
```

Harness 默认地址为 `http://127.0.0.1:3080`。本轮固定 `@deepseek-ai/dsh@0.1.6-alpha.2`。首次使用先在 `integrations/deepseek-harness` 执行 `npm ci`，再回到仓库根目录启动，并在 Harness 中配置自己的模型凭据，详见运行文档。没有模型凭据时，业务工作台、行业计算和自动化测试可以独立运行。

## 使用判断

DeepSeek Harness 的插件结构适合扩展商业工具，官方提供本地 Web 会话和插件入口；官方同时标注为开发者预览，可能发生不兼容变化。因此本项目使用独立适配层，并固定验证版本。这个选择是否优于其他运行时，需要用同一组业务任务比较完成率、证据准确度、耗时、费用和维护成本，不能仅从框架名称得出结论。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)

本轮所称“专家分析”均为 AI 辅助的多专业视角预分析，没有真人专家签名。能源、车辆、财税、法律和 ESG 的正式判断须由对应责任人基于具体市场和项目复核。
