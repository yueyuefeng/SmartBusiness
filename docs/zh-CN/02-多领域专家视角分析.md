# 02 多领域专家视角分析

## 1. 分析性质与顺序

输入：[专业词汇 v0.1](01-专业词汇与统一语言.md) 和用户初始目标。当前由 AI 从不同专业视角进行预分析，**没有真实专家参与、签名或会审结论**。下表为供业务专家验证的挑战问题和候选裁决。建模基于这些暂定结论，不能伪称已获专家一致认可。

## 2. 多领域交叉分析

|视角|重点词汇|发现的风险或冲突|建模建议|真实专家需提供的验证材料|
|---|---|---|---|---|
|市场情报|T03/T04/T06/T08|高可信来源也可能提出错误判断|来源评分与结论评分分离；冲突证据可并存|一项被证伪情报及更正流程|
|产品与业务分析|T11/T12/T16/T20|客户一句话可能含多个需求，也可能只是一种方案|诉求到需求多对多；保留原话和拆分依据|5 条原始诉求及验收反例|
|决策科学|T23/T24/T26/T28|权重和成本主观；总分掩盖否决条件|先硬约束过滤，再做多准则评分与敏感性分析|一次被否决的高分方案|
|财务与经营|T30/T69/T78|合同金额、商机预测、回款和收入混淆|保留各自口径；财务系统为记账权威|财务口径表及项目现金流样本|
|销售 / 客服|T31/T32/T33/T38|同名客户误合并；会话不等于客户|身份关联需证据；客户时间线为跨会话投影|客户转移、离职、重名案例|
|渠道集成|T37/T40/T41/T44|接口接受不代表送达；账号类型决定能力|能力声明和运行时校验；保留未知状态|真实授权应用和消息回执样本|
|软件工程 / 测试|T15/T46/T50/T54|工作项关闭不能证明需求满足|需求—测试—构建—发布可追踪|一次回滚和未通过验收案例|
|硬件 / 供应链 / 质量|T56/T59/T61/T68|替代料影响固件、性能、认证与采购|受控修订；ECO 分析软硬件影响和批次生效|BOM、工程变更与样机试验记录|
|合同 / 法务|T70/T72/T74/T77|内部审批不是有效签署；技术测试不是客户验收|分离批准、签署、义务完成、客户验收|脱敏合同、授权链及争议案例|

|安全 / 隐私|T44/T101/T102/T106|跨客户搜索或训练泄露；删除与保全冲突|租户权限前置检索；按用途授权；例外有审批依据|数据地图、处理依据与保留清单|
|交互 / 多端|T38/T77/T102|离线操作和不同端权限导致重复或过时审批|离线草稿；服务端权威；高风险操作在线复核|现场弱网、设备与辅助功能需求|

## 3. 同词异义裁决表

|歧义|必须区分|暂定边界裁决|验证责任|
|---|---|---|---|
|客户|CRM 的 CustomerAccount / 合同的 ContractParty|CRM 当前信息不能覆盖已签合同主体快照|销售 + 法务|
|需求|原始意图 / 已确认需求 / 工作项|由需求上下文维护澄清与基线；交付维护执行|产品 + 工程|
|批准|需求确认 / 决策批准 / 合同签署 / 发布批准|分别使用明确命令和授权策略|各域负责人|
|版本|需求修订 / 代码提交 / BOM 修订 / 合同版本|只用显式链接互相映射，不共享一个全局 version|工程 + 法务|
|完成|代码合并 / 测试通过 / 上线 / 客户验收|分别发生事件，互不自动等价|测试 + 交付|
|证据|情报引用 / 签署记录 / ESG 凭证|平台提供存储，领域拥有用途、有效性和访问规则|法务 + ESG + 情报|
|重大性|经营优先级 / 财务重大性 / 影响重大性|三套规则分别定义；不得复用单一阈值|财务 + ESG|
|成本|商机预估 / 决策区间 / 实际成本 / 采购价格|值带币种、时间、来源和是否估计|财务 + 供应链|
|发布|软件可分发 / 合同对外发出 / 报告正式发布|不同聚合、不同行为和证据门槛|工程 + 法务 + ESG|
|主体|租户 / 公司法人 / 客户 / ESG 报告实体|采用独立 ID，跨域用授权映射关系|架构 + 法务 + ESG|

## 4. 冲突的处理与建模依据

- D01：客户关联错误会污染合同与沟通，身份合并必须可撤销并保留关联依据 → CRM 拥有 IdentityLink。
- D02：原始消息不能随需求整理消失 → 沟通域拥有 Message；需求域仅保存授权引用和必要摘要。
- D03：决策分数可能受选择性证据影响 → DecisionCase 固定证据版本、权重、假设和异议。
- D04：同一需求同时涉及软件和硬件 → 需求基线跨域引用，两个交付上下文独立管理修订。
- D05：合同变更跨越预算、BOM、发布 → 长事务协调器跟踪状态，不跨上下文强行一个数据库事务。
- D06：报告数据与实时看板用途不同 → 冻结报告快照，经营分析只读投影。
- D07：官方渠道授权不可假设通用 → 各适配器声明能力，用策略和错误码表达限制。

以上 D01–D07 为候选分析决议，不是业务签字结论。

## 5. 正式评审方式

拟分三轮：词汇评审（业务/法务/工程/ESG）→ 事件与规则评审 → 模型与示例评审。每项结论记录支持证据、反对意见、裁决人、有效范围、待验证项。

进入生产开发前，至少确认首期需求的词汇、身份归属、授权动作、合同生效前置条件、渠道权限和验收例；其余阶段的议题可按路线逐步确认。不能为了形式完整而阻塞与这些未知项无关的开发准备工作。

## 6. 用户补充后的跨专业分析 v0.2（领域模型输入）

|视角|新增词汇|交叉争议|候选裁决 / 业务验证材料|
|---|---|---|---|
|创业经营 / 商业模式|T107/T113/T115/T137|发现需求不证明客户愿意付费；评分高不保证盈利|先小额验证支付意愿、供给与成本，再批准投入；提供一次成功和失败生意|
|资源整合 / 采购|T108–T112/T126|资源“能做”不代表当前有产能或有效报价|能力证据带有效期，分离匹配、供应商准入和订单承诺；提供询价样本|
|营销 / 内容 / 增长|T117–T123|曝光不等于获客，归因不等于增量收益|冻结内容版本和发布审批，把活动连接到客户、订单和利润；提供内容及转化样本|
|内贸 / 外贸运营|T124–T129/T138/T142|售价不能反映运输、关税、汇率和售后承担|报价必须声明贸易条件、地点、币种和成本假设；由贸易人员核定责任|
|会计 / 财务|T130–T140|中介成交额可能不属于自身收入；回款不等于利润|按商业路径区分佣金和自营销售收入；保存收入/成本口径、退款和汇兑差异|
|售后 / 质量|T141/T143|销售闭环在退货、质量和保修时重新打开|退货退款产生更正与冲销记录，追踪批次和客户反馈|
|安全 / 法务 / 品牌|T119/T120/T44|内容助手可能编造产品性能或越权发布|事实声明引用已核实材料；授权账号、用途、内容版本和审核记录必须一致|

追加裁决：
- D08：MarketOpportunity 与 CRM Opportunity 分离；市场机会可产生多个客户商机。
- D09：BusinessModel 和 Experiment 是需求变现的核心模型；实验失败保留结果并停止无效投入。
- D10：资源匹配必须同时展示不满足项与不确定项；AI 分数不能替代样品、审厂或资质核实。
- D11：营销发布与客户私信分别建模，不能用“万能发送消息”掩盖公开发布语义。
- D12：每种生意都必须指定收入机制、履约成功条件、成本结构、回款节点与复盘口径。
- D13：ProfitSnapshot 是经营核算视图，财务记账与法定报表仍由经确认的财务系统/规则负责。
- D14：硬件产品研发与库存商品销售可独立存在；系统应支持转售现成产品，无须先走研发流程。

上述仍是多领域预分析建议，未进行真人专家会审。后续领域模型使用 v0.2 词汇与 D01–D14 作为输入。
