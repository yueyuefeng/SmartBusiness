# 03 业务需求与验收标准

基于 v0.2 词汇及多领域分析。P0=首个可用闭环；P1=扩展与深化；P2=规模化。优先级是建议，未由用户确认工期。

## 1. 功能需求

|编号 / 优先级|领域与用户目标|范围与验收标准|
|---|---|---|
|R01 / P0|情报：快速捕获市场需求|手工录入、授权文件/消息引用和来源订阅；保留来源、采集时间、摘要与使用范围。相同内容重复导入不重复建立证据；访问受限来源不出现在无权限搜索中。|
|R02 / P0|需求：归类并验证痛点|诉求去重、拆分合并、分类体系版本、证据关联和人工确认；AI 建议可拒绝。未写验收条件或负责人不能确认需求。|
|R03 / P0|资源：寻找并比较供给|资源档案、能力证据、供应商联系方式、人工检索与匹配；结果显示约束满足情况与报价有效期。过期能力证据不得标为已核实。|
|R04 / P0|商业模式：设计如何赚钱|客户群、价值、收费方式、资源组合、成本、渠道、风险和实验计划版本化。信息中介、软件服务、硬件销售均能建立模型；无收入机制不能提交投入评审。|
|R05 / P0|决策：明确投入与停止|比较方案、硬约束、权重、证据、预算、批准与复盘。权重不合法、缺证据或越权批准被拒绝；批准固定版本不被后续改稿覆盖。|
|R06 / P0|客户：把沟通转成商机|客户、联系人、线索、商机、跟进、服务工单；同名不同客户保持分离。身份合并有依据、可复核与撤销。|
|R07 / P0|沟通：统一授权渠道收件箱|一个真实官方渠道完成接入、会话指派、内部备注、附件和回复；重复回调只有一份业务消息，发送未知状态显示待核对，不能假报送达。|
|R08 / P0|营销：内容制作助手|根据简报生成文字草稿、图像/视频脚本、多语言改写；记录来源、素材权利、品牌与产品声明。未经证实的性能/交期/ESG 主张标记待核实；AI 无权直接批准。|
|R09 / P0|营销：发布助手|内容审核、渠道预览、定时任务、结果追踪。首期支持经确认渠道的发布或导出发布包及人工回填；编辑已批准内容须重新审核，失败/未知不能显示发布成功。|
|R10 / P0|营销：获客反馈|活动/内容/发布 ID、带参数链接或表单、线索来源和关联订单。手工归因注明依据；一个订单的同模型权重总和为 1，重复回调不重复计转化。|
|R11 / P0|交易：报价与订单|产品/服务要约、价格币种、税费口径、范围、条款、有效期和客户确认。过期报价必须重审；订单保留当时快照；客户更改当前地址不覆盖订单历史。|
|R12 / P0|合同：条款与履约|合同草稿、模板版本、内部评审、人工上传签署件、义务与变更；签署后只允许补充版本。首期不依赖电子签 API，后续接入需验证签署证据。|
|R13 / P0→P1|履约：多种生意共用闭环|P0 支持任务、里程碑、证据和验收，选择一种生意完成试点；P1 增强其他路径。中介按佣金触发条件，软件按约定验收，商品按交付/退货规则，不强制所有交易走研发。|
|R14 / P1|软件：工程交付与 TDD|需求关联测试场景、工作项、代码提交、构建、发布、部署和验收。未经测试证据和批准的构建不进入可发布状态；发布失败保留回滚记录。|
|R15 / P1|硬件：设计到质量反馈|料号、BOM 修订、图纸文件、固件兼容、样机、ECR/ECO、试验和供应商。已发布 BOM 不可原地改；未授权替代料不能用于受控基线。|
|R16 / P1|贸易：采购和实物交付|询价/比价、采购单引用、交付节点、物流/单证、批次、售后；内贸与外贸字段按规则包要求。库存初期引用已有系统，数量不足显示待协调，不臆造可用量。|
|R17 / P0|利润：量化经营结果|人工录入或导入收入、成本、回款并附凭证；提供预估/暂估/已核对状态，分别展示毛利、贡献利润、现金。缺成本时明确“不完整”，不能输出“最终净利”。|
|R18 / P1|财务：对账与更正|应收应付、退款、手续费、汇率、成本分摊、期间费用外部引用；重复导入不重复记账，更正保留原记录和反向/调整关联。法定会计由专业系统负责。|
|R19 / P1|ESG：证据到报告|配置报告边界与准则版本、E/S/G 指标、数据收集、复核、计算和报告快照。缺失不得当零；因子变更不改变已发布报告，可按新版本重算并说明差异。|
|R20 / P0|经营分析与复盘|市场机会—实验—活动—线索—订单—交付—利润链可钻取；看板显示数据时间、币种、完整度和归因口径。可记录继续/调整/停止结论并创建新一轮实验。|
|R21 / P0|平台：权限、审计与文档|租户隔离、角色和对象权限、审计、数据导出及删除流程；一名销售不能检索另一租户信息，受限合同成本不能因汇总看板泄露。|
|R22 / P0→P1|多端：连续工作|P0 在选定试点端完成核心流程并五端构建验证；P1 五端功能验收。移动端采集/沟通/轻审批，桌面深度分析/文档；离线草稿冲突提示，审批与外发要求在线校验。|
|R23 / P1|AI：可控助手|检索、分类、匹配、模式建议、内容草稿、合同差异、报告草稿均附输入证据与版本；低置信度交给人处理。费用、延迟和人工改写比例可追踪。|

## 2. 端到端验收场景

|场景|输入 → 关键行为 → 可观察结果|
|---|---|
|E2E-01 信息中介|需求证据 → 核实供需 → 约定佣金 → 撮合成功证据 → 佣金到账与成本 → 贡献利润复盘；成交总额不计入自身佣金收入。|
|E2E-02 软件交付|需求基线 → 资源工时估算 → 报价签约 → TDD 交付 → 客户验收 → 收款与真实成本 → 返工对利润影响。|
|E2E-03 硬件销售|需求 → 自研或现货选型 → 样品/规格确认 → 内容获客 → 订单 → 采购/生产/物流 → 售后 → 利润；可选择绕过研发。|
|E2E-04 跨境变更|外币报价 → 运费/汇率变化 → 超出利润底线 → 重新审批 → 新报价版本；不得静默修改已接受订单。|
|E2E-05 营销闭环|实验假设 → 内容版本 → 审核发布 → 线索 → 商机 → 订单 → 扣退款和获客成本后的利润 → 下轮策略。|
|E2E-06 ESG 更正|用能凭证 → 指标计算 → 复核发布 → 原始数据更正 → 新报告快照及差异；旧报告仍可按历史输入复现。|

## 3. 非功能需求（目标，尚未实测）

|编号|目标|验收方法|
|---|---|---|
|N01|试点基线：100 并发交互用户、10 条/秒持续入站、100 条/秒 60 秒突发|采用脱敏合成数据测压；实际预算/规模确认后调整，外部 API 额度单独计算|
|N02|上述基线下常见读 API P95≤500ms、写入受理 P95≤800ms；附件、AI 与外部等待排除并单列|记录环境、数据量、测量窗口和错误率；消息持久化到收件箱可见 P95≤5 秒|
|N03|生产目标月可用性 99.9%；内部核心数据 RPO≤15 分钟、RTO≤4 小时|备份还原和故障演练验证；第三方停机单独展示，未部署前不宣称达到|
|N04|高风险命令记录操作者、租户、对象版本、授权依据、关联 ID 和结果|抽查审计与业务命令关联，日志脱敏且不存访问令牌|
|N05|五端适配中文/英文、时区、币种及无障碍基础交互|真机/原生系统分别检查登录、导航、输入法、附件、通知和弱网|
|N06|权限优先于检索与 AI；上传文件检查类型、大小、恶意内容及引用权限|跨租户、越权对象、提示注入、恶意附件和失效链接测试|
|N07|数据可导出，模型和策略可版本化，删除与保全可追踪|导出重放、删除对索引/缓存/附件传播及例外审计测试|
|N08|文档全中文，需求—规则—用例—代码—发布双向追踪|文档链接和追踪矩阵检查；英文标识有中文业务定义|

## 4. 不作为首期承诺

全平台自动发帖或私信、自动成交获利、无授权数据采集、全自动签约付款、完整财务总账、通用 CAD 编辑器、实时全球库存、无需专业复核的法定 ESG 报告均不属于首期承诺。可在真实业务和接口验证后逐项扩展。
