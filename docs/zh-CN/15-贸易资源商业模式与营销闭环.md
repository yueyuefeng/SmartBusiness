# 15 贸易、资源、商业模式与营销闭环

## 1. 产品主张

用户明确目标是快速获取市场需求、寻找资源、构建商业模式并实现利润。系统通过更快反馈、更少信息丢失和可核对的经营结果支持这个目标，但不承诺某种商业模式一定成功。

主要工作台：
1. 机会雷达：信号、痛点、证据、新鲜度、客户群与竞争替代。
2. 资源地图：供应、技术、服务、渠道、资质、产能、报价与可接洽方式。
3. 生意设计台：商业模式、单位经济、实验、方案对比、投入和停止规则。
4. 营销工作室：内容简报、制作助手、素材版本、审核、发布日历与线索。
5. 统一客户台：会话、客户、商机、报价、合同、订单和售后。
6. 交付控制台：采购物流、软件工程、硬件工程或中介服务。
7. 经营驾驶舱：收入、成本、回款、贡献利润、数据缺口及复盘。
8. ESG 工作台：指标证据、口径、报告和更正。

用户进入一笔生意时，能沿关联链查看“为什么做、用哪些资源、向谁销售、如何交付、是否赚到钱、下一步是什么”。

## 2. 三种商业路径

|项目|信息中介|软件交付|硬件/商品销售|
|---|---|---|---|
|价值|降低供需寻找和交易成本|解决客户流程/业务问题|提供满足用途的实物产品|
|资源|买卖双方、行业信息、信任与渠道|团队、组件、技术、交付能力|供应商、现货或自研产品、制造和物流|
|收费|成功佣金、订阅、服务费等约定|项目、里程碑、订阅、维护费|销售价、服务和维护收入|
|履约证据|介绍/成交及佣金触发条件证据|合同范围、测试、版本、验收|规格/批次、发运签收及约定验收|
|主要成本|获客、核实、合作方分成、人员|工时、云资源、外包、返工和维护|采购/制造、物流、保险、税费、库存和售后|
|主要风险|撮合成功但无法收佣、主体角色争议|需求蔓延、验收拖延、估时不准|质量/库存/交期、运费、汇率、退款|
|反馈|资源质量、客户重复需求、撮合转化|真实使用价值、缺陷和续费|退货原因、缺陷批次和复购|

订单业务类型可以组合，但每种收费项必须指定履约条件和核算口径。中介同时兼任经销商时，不能仅凭界面选择就确定总额/净额收入，需财务结合实际角色确认。

## 3. 资源发现与整合

来源可包括自有名录、用户授权的平台数据、客户推荐、供应商提交、公开许可来源与人工调研。每条资源保留来源、联系人授权、覆盖地区、能力、产能区间、价格有效期、最小起订量、交期、资质证据和最近核实时间。

匹配先过滤硬条件（规格、地区、时间、预算、准入要求），再比较软条件（价格、稳定性、沟通、过往交付）。输出每项条件的满足/不满足/未知及证据。缺项不能默认满足；伙伴承诺和历史结果分开。支持多资源组合，例如“方案商 + 工厂 + 物流 + 渠道”，每个环节有责任接口和备选资源。

RFQ 统一规格和报价口径；比价前核对币种、含税状态、运费、数量阶梯、有效期、交期和贸易条件。价格最低不等于落地成本最低。

## 4. 商业模式与实验

BusinessModel 必含客户群、痛点证据、价值主张、供给资源、销售渠道、收费机制、成本结构、关键活动、约束与失败条件；保存假设置信度而非假装已验证。

每个 Experiment 明确：
- 假设，例如“某类客户愿为指定交期支付某价格”。
- 可观察指标、样本定义、最低样本量、成功/失败/无结论阈值。
- 测试方法：访谈、落地页、小额试单、样机演示或付费试点。
- 预算上限、期限、负责人、停止条件和观察记录。
- 复盘：实际结果、偏差、替代解释、继续/调整/停止决定。

例：10 个合格客户访谈中的 4 个表达兴趣，只能说明访谈反馈；不能直接写“40% 成交率”。付费意愿、真实成交、履约后利润分别验证。实验阈值是启动前设定的业务假设，不由事后结果倒推。

## 5. 营销内容与发布闭环

Campaign → ContentBrief → ContentRevision → Review → PublicationJob → Touchpoint → Lead → Opportunity → Order → ProfitSnapshot → CampaignReview。

制作助手包括选题、受众分析、卖点整理、脚本、文案、翻译本地化、标题变体、素材复用与平台规格检查。产品性能、价格、交期、客户案例、认证与 ESG 声明都必须引用有效证据；不把模型建议写成既成事实。

每个平台有独立版本，内容哈希与审核绑定。排期保存时区与 UTC 时间，并在执行前再次确认授权、内容审批、账号与预算限制。用户授权当前任务是设计，不代表本次已获准向任何社交平台实际发内容；本轮没有外发。

发布成功需平台内容 ID 或核实过的人工凭证。评论/私信成为线索时保存来源和联系授权，不默认把所有观看者导入 CRM。

首期归因采用明确的一种模型，例如最后一个可识别合格触点；同单多触点模型权重总和为 1。不明来源记“未知”，不能为了报表完整强行归因。退款和取消对归因收益做后续调整。展示触达、互动、合格线索、成交、获客成本、贡献利润等漏斗；曝光增长不能独立证明盈利。

## 6. 内贸与外贸字段

|类别|两者共用|外贸/特定交易按条件扩展|
|---|---|---|
|客户与资源|主体、联系人、资质、信用及责任人|地区、语言、时区、跨境对手方核查记录|
|报价与合同|范围、数量、币种、税费口径、有效期、支付条件|贸易术语及版本/地点、多币种、运输和保险责任|
|产品与单证|规格、批次、检验和交付文件|商品编码/原产地/商业发票/装箱/运输/报关等字段，是否必需由具体贸易规则确定|
|物流与售后|发运、签收、退货、质保|跨境路线、清关事件、跨境退货与责任说明|
|利润与现金|价格、收入、成本、收付和对账|运保费、关税等适用支出、收汇手续费、汇率/汇兑差异|

Incoterms® 记录规则版本、代码和指定地点，用来表达相关责任、成本与风险安排；不能代替完整销售合同或付款约定。参见 S15。系统不自动判断任一地区的税率、退税、商品准入或出口限制；按交易和地区维护经专业确认的规则包。

## 7. 利润口径与演示数据

先定义业务类型、期间、币种、含税/不含税、汇率用途和成本归集规则。以下为管理核算演示，数值虚构，不是会计政策或收益预测：

|场景（人民币）|收入与成本假设|毛利|贡献利润|
|---|---|---|---|
|中介|促成交易 100,000；本企业经确认佣金收入 8,000；直接服务成本 2,000；可变获客成本 1,000|6,000|5,000|
|软件|经确认收入 100,000；直接交付人工 60,000、项目基础设施 5,000；可变获客成本 10,000|35,000|25,000|
|硬件|销售收入 150,000、退款调整 5,000；货物与约定落地销售成本 105,000；可变获客 10,000、额外手续费 3,000|40,000|27,000|

示例口径：
- 净收入 = 已归属收入 − 退款/折让等收入调整（不重复扣减）。
- 毛利 = 净收入 − 对应销售/直接服务成本。
- 贡献利润 = 毛利 − 尚未计入上项的可变获客和履约等成本。
- 净利润还需期间费用、融资及税项等按专业口径处理，以上不能称净利润。
- 现金净流入 = 实际流入 − 实际流出，与上述利润可以不同。

每笔成本标明类别、所属订单/活动/期间、已计入口径、分摊基准和凭证，避免同一运费或营销费扣两次。共享成本分摊比例须合计为 1；缺省不能默认零。报价预计利润、暂估经营利润、已核对经营利润分别展示。跨币种保留原币和报告币，注明汇率与时点；汇兑损益单列。

看板至少显示贡献利润、成本完整度、未对账金额、应收逾期和现金流。R17 的验收不要求系统证明利润“最终正确”，而要求可追溯、可核对、缺口可见。

## 8. 闭环复盘和自动化边界

复盘比较机会假设、资源表现、实验数据、营销归因、真实履约和实际经济结果。失败交易也有完整记录，可触发更换资源、调整产品/价格/渠道或停止。

助手可自动生成待办和建议；增加支出、合同承诺、实际采购、付款、公开发布与客户外发由已配置授权流程执行。若未来允许有限自动化，需要明确适用范围、金额/次数上限、退出条件、撤销/补偿机制与负责人。
