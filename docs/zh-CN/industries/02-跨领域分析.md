# 02 多领域专家视角预分析

顺序：先完成 [60 个行业词汇](01-行业词汇.md)，再进行本分析，之后才建立场景和模型。本稿为 AI 辅助预分析，未召开真人专家会审。

|视角|质疑与冲突|设计裁决|需要真实验证|
|---|---|---|---|
|能源系统|储能容量足够不代表能带动负载；电热不能直接相加|同时验证功率、能量、初始状态和效率；热泵显式变换电/热|场址负荷、单线图、设备数据和设计工况|
|暖通/建筑|热泵 COP 随工况变，储热有损耗|热状态独立；样例 COP 为给定工况假设，不作全年结论|热需求、温度曲线、可用空间与建筑条件|
|电气/消防|产品测试报告不等于场址允许安装与孤岛运行|产品组合与安装审核分离；市场未确定不放行现场实施|当地工程审核、并网和安装许可适用性|
|储能经营/财务|削峰和套利不能重复占用同一电池；短期数据不证明年收益|同一逐时调度核算；不完整计费期禁止需量费和年度回报结论|全年/完整计费周期负荷、电价、寿命与保修|
|出行法规/产品|电动自行车、电助力和摩托称谓不能跨地区直接套用|地区规则包、产品特征和版本化分类记录；不做“全球合法”按钮|目标市场和具体产品分类审查|
|机械/车辆|套件能安装不代表原车可承受；制动工况会改变|改装绑定原车与套件版本；结构/制动/电气/充电组合独立证据|原车检查、整车试验与安装者能力|
|供应链/质量|电芯证书不是整机证书；供应商报告可能对应其他版本|证据绑定市场、产品修订、用途和有效日期|报告真伪与范围核对、供应商准入|
|营销/渠道|“省一半电费”“保证续航100公里”可能超出证据|每个声明绑定测试条件、证据与内容版本；未知项不能外发为确定承诺|试点实测、品牌/技术审核和账号权限|
|法务/售后|改装后原车、套件、安装者责任交叉；能源分成有基线争议|合同附件写明边界、工况、验收、质保、退出和争议方法|正式合同与当地责任安排|
|数据/软件|家庭行为和骑行轨迹可关联个人；遥测不等于财务事实|最小数据、明确用途；设备控制与商业系统隔离|真实数据授权与遥测准确度|
|ESG|储能和电动出行不自动等于减碳|按边界、基线、能耗、寿命和因子计算；经营节省不能直接折算碳收益|生命周期或运营核算的口径与证据|

## 关键冲突决议

- ID01：家庭光储备电和电热协同分成两种场景；商业储能再独立，不能共用单一 ROI 算式。
- ID02：供应商收益、业主能源经济性和环境表现分别核算。
- ID03：商业平台维护计划、记录和审批；不直接控制 PCS/BMS、电机或安全保护。
- ID04：所有案例必须有目标地区字段；未知地区输出待确认，而不是默认中国/欧盟规则。
- ID05：电动摩托不参与电助力自行车数值阈值的“放行”；必须走其独立分类与审批路径。
- ID06：改装需组合级证据；套件证书不能自动为旧自行车背书。
- ID07：资源匹配采用满足/不满足/未知，逾期、错版本和缺失证据不能计作满足。
- ID08：营销和实际交易沿用公共闭环；行业模型只增加行业特有约束。
- ID09：储能收益缺少完整计费周期就不计算需量费节省；不从一天数据外推全年。
- ID10：可执行样例使用虚构输入，只证明规则行为；输出禁止表述为实际销量、实际利润或真实认证结果。

## 实施裁决

现有环境具备 Python，未发现 Java/JDK 构建工具。本轮以 Python 标准库实现“可执行领域规格/行业验证内核”，用于自动运行行业案例与 TDD，不替换此前 Java + Flutter 的生产候选架构。可把 JSON 夹具和预期结果迁移为生产端契约测试。

真实专家评审应先确认首个市场、行业术语、数据样本、设备/车型分类、交付责任与利润口径。其余通用代码和脱敏样例可先行完成。
