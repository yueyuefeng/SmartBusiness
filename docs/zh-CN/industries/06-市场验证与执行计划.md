# 06 市场验证与执行计划

## 1. 已确认与未确认

用户确认行业与大区域：欧美、国内一二线城市。尚未选定国家、美国州/城市、国内城市、已有资源、预算与团队。本计划不假定已经具备供货/准入能力，也不以示例数值估计真实市场规模。

把“欧洲”拆至具体国家，“美国”拆至州/城市/电力公司，“国内一二线”拆至具体城市、场址和用途。英国规则只作独立参考，不当作欧盟规则。

|市场组|储能优先验证|出行优先验证|当前状态|
|---|---|---|---|
|欧洲待选国|家庭安装条件、电价机制、当地安装商、热泵/储热需求、并网路径|客户工况、车型分类、进口/经销责任、服务网与改装责任|待研究与访谈|
|美国待选州|用户电力公司费率、备电痛点、安装/消防、合作方和售后|州/地方使用规则与联邦产品要求的关系、充停、渠道与责任|待研究与访谈|
|国内待选城市|商业客户负荷、场地权限、计费与并网、家庭真实安装条件|车型与登记/通行、客户用途、充停和服务能力，改装路径先核查|待研究与访谈|

不凭单一电价差、网上热度或关键词搜索量排序。候选市场矩阵记录“证据来源/日期/适用范围/未知项”，未采集数据前不输出伪精确评分。

## 2. 首轮实验组合

以下数量与阈值是**建议的实验设计**，不是市场事实或已取得结果；投入预算先由业务负责人确定。

|实验|样本与动作|预登记判断条件|不满足时|
|---|---|---|---|
|EXP-EH 家庭需求|每个候选市场访谈5个有安装条件家庭和2个安装商|至少2个愿提供授权数据并接受明确价格范围的下一步诊断；核实一家可承担交付的伙伴|改客户定位或暂停，不把口头兴趣算成交|
|EXP-EC 商业诊断|访谈5家商业客户，争取2套授权账单/负荷样本|至少1套覆盖所需计费窗口并能解释费用，客户认可诊断价值|先解决数据取得和诊断服务，不采购设备|
|EXP-ME 自行车|访谈10名目标用户、3家服务门店|至少3人愿进入明确条件的试骑/评估，1家门店愿核算真实售后工时|调整产品与服务半径|
|EXP-MM 摩托|访谈3家经销/车队客户与2家供方|至少一个明确需求、市场路线、服务责任和成本结构的试点机会|不大量库存|
|EXP-MK 改装|征集5份经同意的原车资料，邀请合适专业人员评估|至少2份存在可继续检查的技术与市场路径，安装者愿承担明确责任|改为诊断/整车推荐服务，不强行套件销售|

进入真实接洽前须确定沟通对象与授权。本次只创建模板和案例，未发送消息、未招募用户、未支付或订货。

## 3. 可直接使用的客户访谈表

- 访谈编号、日期、同意范围、市场和具体使用地点。
- 最近一次遇到问题是什么？发生频率、实际损失和当前替代方案？
- 谁使用、谁付款、谁能批准安装/改装/车辆采购？
- 可提供哪些原始资料？哪些可以用来做方案、营销、转交供应商？
- 理想结果与最低可接受结果分别是什么？有哪些绝对不可接受条件？
- 目前花费/预算如何确定？愿为哪一步付费？是否接受诊断价格或小额试单？
- 谁负责现场、售后、退换货？已有合作方是谁？
- 访谈原话、推断、已核实事实分栏记录；记录拒绝理由，不只记录赞同。

## 4. 资源询价表

资源ID / 联系来源与授权 / 公司与责任主体 / 目标市场 / 产品组合与修订 /
技术参数及单位 / 证据文件与适用范围 / 产能和交期 / 报价数量阶梯 /
币种、税费和贸易条件 / 运输与保险 / 安装、检测、售后和备件 /
质保与排除 / 报价有效期 / 信息核实人和日期 / 风险与未知。

先形成可比较的 RFQ，再收报价。报价过期、不同修订或地区证据不能直接排序推荐；本轮虚构资源A/B用于验证此规则。

## 5. 试点节奏与责任

|阶段|工作包|责任角色|退出证据|
|---|---|---|---|
|G0 市场选择|为每行业选一个具体市场、客户类型与收费路径|业务负责人+贸易/地区顾问|候选比较、未决项、投入上限|
|G1 需求和供给|访谈、授权数据、RFQ、合作交付能力|客户经理+资源经理+行业专家|原话、证据、资源核实与成本结构|
|G2 小额验证|诊断、方案评审、内容草稿、付费意愿/试单|产品+工程+营销+财务|实验结果、报价版本、风险与止损结论|
|G3 单笔履约|合同、安装/交付、验收、售后和核算|交付负责人+当地专业伙伴|真实订单与合同、验收、收付/成本凭证|
|G4 复盘|利润与预测差异、客户反馈、资源质量与改进|经营者+财务+产品|继续/调整/停止决定和下轮实验|

时间和预算尚未锁定；上表是退出条件，不是保证几周能完成真实交易。建议两行业各先选一条路径，避免六个场景同时投入重资产。

## 6. 共用中文交付清单

每笔试点形成：情报条目 → 需求卡 → 行业评估 → 资源比较 → 商业模式与实验卡 → 内容简报/批准版本 → 线索与商机 → 报价/合同 → 交付基线与验收 → 收款成本 → 利润快照 → 复盘与 ESG 证据引用。

案例 JSON 的 trace ID 展示这些关联，当前均为合成标识。真实应用应在各上下文持久化，不能以示例ID替代实际证据。

## 7. 成功与停止

商业成功由实际支付、合格交付、回款和可核对贡献共同判断；技术测试通过、点赞或留资都不能单独算成功。
先设诊断预算/样品上限，再决定投资；如无付费问题、无合格供给、缺市场路线或完整成本后不可持续，保留失败证据并停止/调整。
